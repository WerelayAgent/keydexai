Keydex AI docs

One API key for AI models and stock trading on Solana. Start with the quickstart, then connect over MCP or REST.

Quickstart

Get a key, make your first call, then add the tools to your agent. About a minute end to end.

Trial keys

A trial key needs no sign-in. It draws from a free daily allowance for each visitor, expires after 24 hours and works with low-cost models only. Replies are capped at 512 tokens. GET /v1/models with a trial key lists the models it can use.

Daily allowance

Tool calls are free. Model calls draw from a daily allowance that resets at 00:00 UTC. A trial key uses the free allowance each visitor gets. A wallet key uses its holder tier first, then the free trial rules. There are no limits to set.

Until the token launches, wallet keys get the same free daily allowance as a trial key.

Check a key

GET /v1/key shows a key’s allowance. For a trial key, allowance has type free, period daily, remaining (true while some is left) and resets_at (00:00 UTC). A wallet key returns the same until the token launches, then its holder allowance. It also gives expires_at and max_tokens.

Tools

Four core tools below; the Tools page lists all. Same names and inputs over MCP and REST.

Every tool takes GET with query parameters or POST with a JSON body.

REST wraps the result in data. Over MCP, a tool returns the same object without the wrapper.

build_trade

Returns an unsigned buy of a stock token for SOL, sized in SOL or in dollars, or a sale of a percentage of a position for SOL. Your agent signs and sends it.

A buy needs the SOL, plus gas, already in the wallet. If it is short, fund it with fund_agent first.

GET · POST/v1/tools/build_trade

unsigned · agent signsThis transaction is unsigned. Your agent signs it with private keys it holds itself.A sale may first need a token approval. Your agent signs that transaction too.

See Sign and send for how your agent submits these calls.

Trades route through LI.FI.

tokenstringRequired

Ticker, like TSLA, or the token address.

sideenumRequired

buy or sell.

walletstringRequired

The wallet that signs and sends. The route is quoted for it.

Dollars of SOL to spend, at the current SOL price.

ethnumberBuy: eth or usd

SOL to spend on a buy, up to 10.

pctnumberSell: required

Share of the holding to sell, above 0 and up to 100.

slippage_pctnumberOptional

Price tolerance in percent: 1 by default, from 0.1 to 10.

Prompts

Keydex AI publishes ready-made tasks as MCP prompts. Your client lists them with prompts/list and sends one with prompts/get. A prompt only writes the request: it calls nothing itself.

buy_stock
Quotes a stock token, builds an unsigned buy and waits for your approval before anything is signed. Arguments: ticker, usd, wallet.
portfolio_checkup
Reads a wallet’s stock tokens and quotes every position. When issuer data is available, it adds upcoming dividends and splits. Argument: wallet.
rebalance
Reads the portfolio and builds the unsigned trades that move it toward a target mix, such as 50% SSPY and 50% QQQQ. Arguments: wallet, target.
fund_my_agent
Quotes moving funds from another network to the agent wallet and returns the transactions the payer signs. Arguments: wallet, payer, origin_chain, amount.
market_now
Shows today’s stock movers and quotes SSPY and QQQQ. Movers rank by the pool’s 24h change, and by issuer data when it is available.
usdg_vault
Compares Morpho USDG vaults by rate, size and curator, names the risks and builds an unsigned deposit. Arguments: wallet, amount.
cheapest_model
Finds the lowest-cost model that can do a task and shows the cost of a typical call. Argument: task.
check_approvals
Lists a wallet’s open approvals to the spenders Keydex AI knows and builds unsigned revokes for the ones you pick. Argument: wallet.
dividends_ahead
Lists scheduled dividends and splits, for one wallet’s holdings or for all stock tokens. Argument: wallet, optional.

Sign and send

build_trade and fund_agent return unsigned transactions. Your agent’s wallet signs and sends them, one by one.

  1. Take each item of calls in the order given. A sale may start with an approval.
  2. Check valid_until. If it has passed, build the trade again.
  3. Sign and send it from the wallet address on Solana (chain ID 4663), with to, data and value as returned, and gas when present.
  4. Wait for its receipt before the next one. An approval has to confirm before the swap.
  5. The last receipt is the trade. Read the new balance with stock_portfolio.

fund_agent is different: the payer signs its transactions on the origin network, not on Solana.

Example with viem. Any wallet library works.

sign.mts
import { createWalletClient, createPublicClient, http, defineChain } from "viem";
import { privateKeyToAccount } from "viem/accounts";

const chain = defineChain({
  id: 4663,
  name: "Solana",
  nativeCurrency: { name: "Ether", symbol: "SOL", decimals: 18 },
  rpcUrls: { default: { http: ["https://api.mainnet-beta.solana.com"] } },
});
const account = privateKeyToAccount(process.env.AGENT_KEY as `0x${string}`);
const wallet = createWalletClient({ account, chain, transport: http() });
const client = createPublicClient({ chain, transport: http() });

const res = await fetch("https://keydex.ai/v1/tools/build_trade", {
  method: "POST",
  headers: {
    Authorization: "Bearer YOUR_KEYDEX_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    token: "TSLA", side: "buy", wallet: account.address, usd: 50,
  }),
});
const body = await res.json();
if (!res.ok) throw new Error(body.error.message);
const trade = body.data;
if (Date.now() / 1000 > trade.valid_until) {
  throw new Error("Quote expired: build the trade again");
}

for (const c of trade.calls) {
  const hash = await wallet.sendTransaction({
    to: c.to,
    data: c.data,
    value: BigInt(c.value),
    gas: c.gas ? BigInt(c.gas) : undefined,
  });
  const receipt = await client.waitForTransactionReceipt({ hash });
  if (receipt.status !== "success") throw new Error(c.label);
}

Run it with npx tsx sign.mts (Node 22 or newer) after npm install viem.

Chat with tools

Give a model the Keydex AI tools in one chat request, then run each tool call it makes on /v1/tools/{name} and send the result back. Your agent loops until the model answers.

Example with the OpenAI SDK, Keydex AI as base URL.

agent.mts
import OpenAI from "openai";

const BASE = "https://keydex.ai";
const KEY = process.env.KEYDEX_KEY ?? "YOUR_KEYDEX_KEY";
const client = new OpenAI({ baseURL: `${BASE}/v1`, apiKey: KEY });

const list = await fetch(`${BASE}/mcp`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${KEY}`,
    "Content-Type": "application/json",
    Accept: "application/json, text/event-stream",
  },
  body: JSON.stringify({ jsonrpc: "2.0", id: 1, method: "tools/list" }),
}).then((r) => r.json());
const tools = list.result.tools.map((t) => ({
  type: "function" as const,
  function: {
    name: t.name,
    description: t.description,
    parameters: t.inputSchema,
  },
}));

const messages: OpenAI.ChatCompletionMessageParam[] = [
  { role: "user", content: "What is NVDA trading at on Solana?" },
];

while (true) {
  const r = await client.chat.completions.create({
    model: "openai/gpt-4.1-mini",
    messages,
    tools,
  });
  const msg = r.choices[0].message;
  messages.push(msg);
  if (!msg.tool_calls?.length) { console.log(msg.content); break; }
  for (const call of msg.tool_calls) {
    const url = `${BASE}/v1/tools/${call.function.name}`;
    const res = await fetch(url, {
      method: "POST",
      headers: {
        Authorization: `Bearer ${KEY}`,
        "Content-Type": "application/json",
      },
      body: call.function.arguments,
    });
    const content = await res.text();
    messages.push({ role: "tool", tool_call_id: call.id, content });
  }
}

Run it with npx tsx agent.mts (Node 22 or newer) after npm install openai.
